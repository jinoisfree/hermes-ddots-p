# CCTV 확인 팩

원격 데스크톱(Windows App)의 CCTV 화면 창 하나만 캡처해, 맞는 채널의 라이브인지 확인한 뒤 장면(평소·준비중·진행중)을
읽고 소유자 방에 "오늘 상황 기록 제안"을 올린다. **상황 기록은 소유자가 버튼을 누른 뒤에만** 시설(`hermes_governance.proposal_decisions`)이
상황을 소유한 플러그인의 실행기를 불러 처리한다. 이 팩은 상황 파일을 쓰지 않는다.

- `watch.py` 한 번의 깨어남(시각 판정 → 캡처 → 식별 → 장면 판독 → 제안). 실행 진입은 직원 홈의 `scripts/cctv_watch.py`가 상황 소유 플러그인의 읽기 함수를 넘겨 부른다.
- `screen.py`·`windows.js`·`reconnect.js`·`focus.js`·`click.js` 창 찾기, 창 하나 캡처(`screencapture -l`), 저장된 장치 다시 열기. 전체 화면 캡처, 자격 입력, 인증서 수락은 하지 않는다. 확인 창이 뜨면 읽고 닫고 알린다.
- `executor.py` 재연결 실행기 `cctv.reconnect`. 윈도우 계정을 여러 사람이 공유하므로 배경 확인은 재연결하지 않고 흑우방에 하루 한 번 제안만 올리며(`cctv_watch.reconnect: ask`), 소유자가 승인한 뒤에만 시설이 이 실행기로 `screen.reconnect`를 한 번 부른다. 팩 등록 때 시설에 등록된다.
- `vision.py` 2단계 판독. 사이트는 강조된 채널의 부모 사이트 줄을 읽고, 고정 트리 폴더명 My Sites·뷰가드서버 장비·로컬 장비·즐겨찾기는 null로 취급한다. 실제 다른 사이트는 계속 거부한다. 1단계 식별(ADT-EYE·채널·LIVE·사이트·기준 구도)을 모두 통과해야 2단계 장면 분류를 한다. 모델은 본 것만 보고하고 판단은 코드가 한다.
- `reference.py` 참고 사진(기준구도·평소·준비중·진행중·비·비아님)과 `cctv_reference` 도구. 소유자 대화에서 최신 글의 첨부 사진 또는 같은 대화의 방금 확인한 캡처 복사본을 저장한다.
- `settings.py` 값의 출처: 켜기·시각 간격·한도는 `owner/policy.yaml`의 `cctv_watch`, 장치·사이트·채널 표시는 금고 `cctv`, 게시 방은 금고 `channels.customer_room`.

상태·캡처는 직원 사물함 `state/cctv/`(수집·공개판 대상 아님)에 둔다. 끄기: `cctv_watch.enabled: false`. 상세는 운영 문서의 해당 절을 본다.

## 연결된 세션 안 라이브 다시 틀기

식별은 시각 `osd_time`(KST, HH:MM/HH:MM:SS 또는 YYYY-MM-DD 접두, 3분 초과 차이·자정 넘김)·`waiting`·`layout_tabs`·`empty_view`·`windows_desktop`도 읽는다.
LIVE 아님·영상 멈춤·다른 채널·레이아웃 없음·빈 화면은 다시 틀기, 바탕화면은 ADT-EYE 켜기 대상이다. 지시서 `relive: auto|off`(기본 auto), `relive_daily_limit`(기본 10)으로 켜기 포함 회차 1회·하루 한도를 제한한다. 재연결은 계속 승인 뒤다.

허용 입력: **금고 app_icon_label과 정확히 같은 바탕화면 아이콘 더블클릭 → 탭 0개일 때만 + → 접힌 장비 트리 삼각형 최대 3회 → 지정 채널 우클릭 → 정확한 라이브 좌클릭 또는 Escape 1회**.
앱은 최대 30초 동안 5초마다 기다리고, 트리는 뷰가드서버 장비→My Sites→site_label만 펼친다. 즐겨찾기·로컬 장비·작업 표시줄·시작 메뉴·다른 메뉴는 제외한다.
채널 순번은 금고 `cctv.channel_index`에서 읽는다(채널명에서 추출하지 않음). item_text는 공백 제거 후 정확히 `{index}.{channel_label}` 또는 `{index}.`만 허용한다. 사이트·즐겨찾기·확신·포함 검사는 유지하고, 번호만 골라도 최종 영상의 채널·LIVE·구도 검사는 그대로다.
최대 3번 펼친 뒤에도 item이 없거나 펼침이 거부되면 입력 없이 5초 간격으로 최대 6번 새 캡처에서 item을 다시 찾은 뒤 실패를 알린다.
인증·로그인·업데이트·불확실한 화면은 누르지 않는다. 앱 종료·탭 닫기·분할·다른 키·드래그는 금지한다. 코드가 글자·확신·상자 포함 관계를 검사한다.

다른 Space의 세션은 Window 메뉴의 rdp_device로 앞으로 가져와 최대 10초 기다린다. `screen.Session` 컨텍스트 하나가 필요한 경우만 활성화하고 회차 끝 finally에서 한 번 복원한다. `click.js`는 복원하지 않고 앞 앱·세션 범위·명령 네 개(right,left,double,escape)만 검사한다. 가져오기·캡처 실패는 focus 알림 하루 1회로 처리하며 재연결을 제안하지 않는다. 복원 실패는 기록만 한다.
좌표는 `X,Y + 상자 중심 비율 × 창 크기(포인트)`이며 입력 직전 창 이동·크기·소멸을 확인한다. double은 click state 1→2다. 새 의존성은 없다.
10초 뒤 식별이 통과한 캡처로 같은 회차 분류를 이어간다. 횟수는 입력 전에 `watch.json relive`에 저장하고 실패 알림은 하루 1번이다. 의도 밖 입력이 보이면 `relive: off`로 즉시 중단한다.

누르지 않는 실제 모델 위치 확인: `python -m hermes_packs.cctv.screen --dry launch|expand|item|plus|live --capture <창 캡처> --window <창 메타데이터 JSON>`.
상자·좌표만 출력하며 입력·활성화는 하지 않는다. 실물 전에 결과를 구현 보고에 기록한다.

## 소유자가 물으면 지금 확인 (2026-11-12)

소유자가 흑우방·소유자 Slack DM에서 현장이나 현재 낙화 여부를 물으면 `cctv_now`를 쓴다.
`reference.Authority.room_problem`으로 매번 권한을 확인하고 고객·예약·단발 실행은 거부한다.
예약 `tick`과 도구는 공개 함수 `watch.check` 하나로 가져오기·캡처·식별·필요한 켜기/다시 틀기·분류·복원을 수행한다.
도구는 감시 시간대와 무관하고 `watch.lock` 경합 시 기다리지 않는다. 원격 재연결과 제안 장부 변경은 하지 않는다.
다시 틀기 한도만 감시와 공유해 입력 전에 저장하며, `last_ask`에 결과를 쓴다. 감시와 소유자 요청 모두 날짜가 바뀌면 지난 판정·오류·질문·재연결·복원·다시 틀기 기록과 하루 카운터를 버린다. 같은 날의 슬롯·알림·연속 실패와 상황 파일은 보존한다.
답에는 장면·이유·영상 시각·확인 날짜(YYYY-MM-DD)와 시각·다시 틀기 여부·캡처 경로와 첨부 결과가 있다. 이미지는 시설의 `learning_report.upload_image`로 같은 스레드에 첨부하며 실패하면 글 결과에 원인을 담는다.
준비중·진행중이면 소유자에게 상황으로 기록할지 묻고 기존 writer로만 기록한다.

`now.py`의 별도 작업 프로세스가 전체 180초 제한을 맡는다. 게이트웨이 도구 스레드와 신호를 공유하지 않고,
145초에서 작업을 중단해 finally 복원과 저장을 위한 35초를 남긴다. 시간 초과 예외는 모델 오류 처리에 삼켜지지 않으며,
열린 메뉴는 Escape 1회로 닫고 화면을 복원한다. 별도 스레드에 입력을 남겨 두지 않는다.

## 소유자가 지금 화면을 가르치면

소유자가 "지금은 ○○ 상태야, 학습해"라고 하면 이름표가 불분명할 때 묻고, 같은 대화에서
지시서 `cctv_watch.teach_check_minutes` 안에 성공·식별된 화면이 없으면 먼저 `cctv_now`를 부른다.
`cctv_reference add from_check=true user_said=<최신 글 인용>`는 `last_ask`의 `chat`·`thread`와 현재
게이트웨이 대화 키를 비교한다. 스레드가 없으면 메시지 ID를 쓰며 DM에도 같은 규칙을 적용한다.
같은 날, 경과 시간이 0~지시서 분×60초(끝 경계 포함), 성공·식별, captures 안의 실제 파일일 때만 복사한다.
다른 대화·미래·만료·잘못된 기록은 `CCTV_REFERENCE_CHECK_REQUIRED`와 재확인 안내를 돌려준다.
감시 잠금 중에도 기록을 읽을 수 있고, 확인 기록·원본 캡처는 바꾸지 않는다. 참고 사진 장부에는
`source: check`와 `osd_time`이 추가된다. `from_check`와 `image_path`는 함께 줄 수 없다.

신선도는 지시서만 읽고 기본값 없이 정수 1~60분을 받는다. 미설정·잘못된 값·enabled가 true가 아니면
`CCTV_REFERENCE_POLICY_INVALID`로 확인 화면 출처만 거부한다. 첨부 사진 add·list·remove와 기존 감시의 필수 설정은 바뀌지 않는다.
첨부 출처는 여전히 최신 소유자 글의 사진만 받으며 앞 글의 사진은 재첨부를 안내한다.
`비`·`비아님`은 CCTV 학습 사진 수집 전용이다. 외부 날씨와 비 판독은 추가하지 않으며,
이 사진들은 낙화 판독 입력·알림·상황 기록·고객 응대에 사용하지 않는다.
